# pulse-agent

[![CI](https://github.com/ru-pulse/pulse-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/ru-pulse/pulse-agent/actions/workflows/ci.yml)

Агент сети мониторинга доступности сайтов [«Пульс Рунета»](https://ru-pulse.ru).
Ставится на обычный компьютер, периодически проверяет по заданию сервера,
открывается ли тот или иной сайт, и отправляет обратно результат.

Смысл сети в том, что проверки идут с **реальных домашних и мобильных
подключений**, а не из дата-центров: только так видно, что сайт недоступен у
конкретного провайдера, и на каком именно уровне — DNS, IP или TLS.

**Код открыт не для галочки.** Вы пускаете программу в свою сеть — значит,
должны иметь возможность проверить, что она делает. Ниже написано, что она
делает, и где именно это в коде.

## Что агент делает

1. Раз в ~25 секунд спрашивает у сервера, есть ли задания.
2. Для каждого задания: резолвит домен, открывает TCP-соединение, делает
   TLS-рукопожатие, отправляет один GET или HEAD и читает **только строку
   статуса**.
3. Отправляет обратно: на какой стадии всё закончилось, сколько миллисекунд
   заняла каждая стадия, HTTP-код и IP, в который резолвится домен.

Всё. Чужой трафик через ваш компьютер не идёт, входящих соединений нет,
содержимое страниц не читается и не передаётся.

Один чек — это примерно 8 КБ трафика, большая часть которых уходит на
TLS-рукопожатие. Точную цифру за сегодня агент показывает в своём окне.

## Что агент не сделает, даже если сервер попросит

Проверяется локально, в этом коде, и сервером не отключается — см.
[`internal/guardrails`](internal/guardrails/) и тесты рядом с ним:

```
$ pulse-agent -limits
  max checks per minute     : 30 (a user setting may only lower it)
  per-target cooldown       : 20s
  max accepted task age     : 5m0s
  allowed methods           : GET, HEAD
  allowed ports             : 80, 443
  private/reserved targets  : refused (checked against every resolved address)
  response body             : never read past the status line, never transmitted
  task authentication       : Ed25519, verified against the key pinned on first run
  privileges required       : none (no root, no raw sockets, no system service)
```

Три вещи, на которые стоит посмотреть отдельно:

**Ваша локальная сеть недоступна.** Задание отбрасывается, если *любой* из
резолвнутых адресов приватный или зарезервированный — включая `192.168.x.x`,
`10.x.x.x`, `127.0.0.1` и облачный метадата-адрес `169.254.169.254`. Роутер, NAS
и рабочие серверы через агента не достать.

**Лимит частоты понижается, но не повышается.** Его можно уменьшить в
настройках; значение выше зашитого потолка молча становится потолком — включая
случай, когда файл настроек правят руками. Иначе заявление «сервер не может
разогнать агента» было бы декоративным.

**Сервер нельзя незаметно подменить.** При первой регистрации агент запоминает
публичный ключ сервера и дальше принимает только задания, подписанные им. Если
ключ изменится, агент откажется работать и скажет об этом, а не начнёт молча
выполнять чужие задания.

## Установка

Готовые сборки — во [вкладке Releases](../../releases): Windows, macOS и Linux,
amd64 и arm64. Скачайте архив, распакуйте, запустите. Права администратора не
нужны: ключ и настройки лежат в домашней папке пользователя (`~/.pulse-agent`).

Под Windows окна нет — только иконка в области уведомлений. По правой кнопке:
запустить/остановить, настройки, журнал, выход.

Из исходников (нужен Go 1.23+):

```bash
make build
./pulse-agent --server https://ru-pulse.ru --partner-code ВАШ_КОД
```

Код партнёра можно ввести и позже — в окне настроек или флагом на уже
работающем агенте: привязка сменится, а накопленная репутация сохранится.

## Настройки

Окно настроек — страница на `127.0.0.1`, которую отдаёт сам агент. Так интерфейс
обходится без GUI-библиотек, и агент остаётся на одной стандартной библиотеке
Go. Порт выбирается случайно, слушается только loopback, каждый запрос требует
токен, выданный при запуске: на машине с несколькими пользователями loopback не
является границей доверия.

В окне: привязка к партнёру, тумблер работы и пауза, лимит проверок в минуту,
трафик и число проверок за сегодня, живой журнал последних проверок.

## Проверить самому

```bash
go test ./...                                  # включая тесты ограничений
grep -rn "exec.Command" --include="*.go" .     # ровно один вызов: открыть браузер
cat go.mod                                     # ни одной внешней зависимости
```

Зависимостей нет вообще — только стандартная библиотека Go. Смотреть нужно ровно
этот репозиторий, без транзитивных пакетов. Это же проверяется в CI: появление
зависимости роняет сборку, чтобы изменение цепочки доверия нельзя было внести
незаметно.

### Проверить, что бинарник собран из этого кода

У релизных архивов есть подтверждение происхождения от GitHub:

```bash
gh attestation verify pulse-agent-<версия>-<платформа>.tar.gz --repo ru-pulse/pulse-agent
```

Сборка воспроизводима: фиксированная версия Go, `-trimpath`, `CGO_ENABLED=0`.
Собрав тот же тег теми же флагами (`make dist VERSION=<версия>`), вы получите
тот же бинарник.

## Статус

Версия 0.1 — ранняя. Сеть работает, но программу пока ставили считанные люди.

Отдельно честно: **иконка в трее под Windows проверена только компиляцией**.
Код Win32 писался и проверялся на macOS, на живой Windows его никто не
запускал. Само выполнение проверок протестировано, а поведение иконки, меню и
автозапуска — нет.

## Известные ограничения

- **Windows покажет предупреждение SmartScreen.** Бинарники пока не подписаны
  сертификатом. Это лечится покупкой сертификата подписи кода, а не изменением
  программы; до тех пор запуск требует «Подробнее» → «Выполнить в любом случае».
- **Права файла настроек под Windows.** Ключ сохраняется с режимом `0600`, но
  Windows не применяет POSIX-права: на общем компьютере `identity.json` доступен
  другим пользователям системы.
- **Эвристика VPN на стороне агента ненадёжна** и заявлена таковой: macOS всегда
  создаёт интерфейсы `utun*`, поэтому там она почти всегда срабатывает впустую.
  Решение о том, находится ли агент за VPN или в дата-центре, сервер принимает
  по адресу соединения, который агент подделать не может.

## Флаги

| Флаг | Переменная окружения | Назначение |
|---|---|---|
| `--server` | `PULSE_SERVER` | адрес control plane |
| `--partner-code` | `PULSE_PARTNER_CODE` | код партнёра: привязка при первом запуске или смена на работающем агенте |
| `--city` | `PULSE_CITY` | необязательная метка города |
| `--identity` | `PULSE_IDENTITY` | путь к `identity.json` |
| `-status` | — | показать привязку и репутацию |
| `-limits` | — | показать зашитые ограничения |
| `-headless` | — | без иконки и окна настроек (для серверов) |
